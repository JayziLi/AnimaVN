## 一、要做的两件事

1. **Jev 一个地方管**:连接(地址、key、测试)、用了多少 token、哪几路交给 Jev、几项共用设置、问法、试判,
   全放在插件抽屉里单独的「Jev」页。各插件页只留「AI 写 / Jev 标」的切换和它自己那道题、门槛。
2. **带上一条回复**:Jev 判每句时多看上一条 AI 回复的最后几句。几句由 Jev 页上的滑条定,默认 24,0 = 不带。

## 二、现在为什么乱

- **key 藏起来了**:要先把某个插件切到「Jev 标注」,下面才冒出「Jev 通用设置」,展开才能填 key。第一次用的人不知道去哪填。
- **同一块放了 5 份**:立绘、背景、音乐、CG、玩家台词每页各一份,内容一样,看着像 5 个设置。
- **一块里塞太多**:key、测试、立绘和文字同步、两条队列、说话人门槛、6 道问法、试判表全在一个折叠块里。
- **看不到全局**:哪几路在用 Jev、有没有 key、用了多少,要一页页翻。
- **地址写死了**:只能连官方 api.typesafe.ai,走中转的人用不了。
- **花费按美元算**:中转的价格不一样,算出来的美元不对。

## 三、新的样子

### 3.1 入口

插件抽屉左栏,插件列表下面单独一项「Jev」(第 2 步草图留的位置)。名字旁边一个小圆点:

| 圆点 | 意思 |
|---|---|
| 绿 | 有 key,上次测试或上次判断是通的 |
| 黄 | 还没填 key(切到 Jev 的插件现在照旧由 AI 写) |
| 红 | 上次出错了(key 不对、连不上、超时),点进去看原因 |
| 不显示 | 没有插件选 Jev,也没填 key |

key 只有 Jev 页一个家。顶栏「API」抽屉(模型连接)最下面加一行只读的「判断模型 Jev:已连上 · 去设置 →」,点了跳到 Jev 页。

样子照第 2 步草图:页头一行说状态,下面一块块,每个设置一行(名字 · 控件 · 管谁 · 恢复默认,下面一句说明)。

**连接这一块的几种情况**

| 情况 | 显示 |
|---|---|
| 没 key | 黄点;「还没填 key,切到 Jev 的插件现在照旧由 AI 写」;输入框直接露出来 |
| 这里填的 key | 密码框显示圆点(不回显),按钮「换一个」「删除」(删除点两次) |
| 后端环境变量 `JEV_API_KEY` | 「key 来自后端环境变量,这里改不了」;不显示输入框 |
| 出错 | 红点 + 原因(「不认这个 key(401)」「连不上 xxx」「8 秒没回」),带「再测一次」 |
| 后端是旧版 | 「后端还是旧版,重启后端」 |

**用量**:像 agent 项目后台那样只数 token,不换算成钱(走中转的价格各不一样)。后端每次问 Jev 都记一笔(判断、试判、测试都算),
按天加起来;页上显示今天 / 这 7 天 / 这个月 / 全部的 token 和请求次数,再加上一条回复的明细。界面上别处原来显示的「约 $0.00xx」都换成 token 数。

**哪几路交给 Jev**:每一路的「AI 写 / Jev 标」和插件页上的是**同一个设置**,改哪边另一边马上跟着变。
中间一列写这一路对当前这张卡实际在不在用、为什么:在用 / AI 写 / 插件关着 / 没 key 退回 AI 写 / 这张卡另设了 / 这张卡没绑素材所以不判。
「详情 →」跳到这一路的插件页:它自己那道题、门槛,以及这张卡绑的素材(Jev 拿素材的说明当选项,改说明就在那里)。
这张卡另设了模式时,这里切的是全局的,那一行写「这张卡另设成 Jev 标 · 详情 →」。

### 3.3 插件页改成什么样

- 「Jev 通用设置」那一整块从 5 个插件页里拿掉
- 每页最上面的模式条不变;Jev 模式下只放自己的东西:
  - 立绘:表情题(高级里)
  - 背景 / 音乐:换场景 / 换音乐的门槛 + 两道问法
  - CG:门槛 + 三道问法
  - 玩家台词:「Jev 认出的玩家台词弹成选项」
- 模式条下面一行「Jev 的连接和共用设置在「Jev」页 →」;没 key 时这行变黄:「还没填 Jev 的 key,现在照旧由 AI 写 —— 去填 →」

### 3.4 和第 2 步「插件页整理」的关系

这一页就是第 2 步要做的「Jev 单独一页」(2.9 第 5 条),先单独做。做法照 2.9:每个设置一行的画法(`SettingRow`)这次先做出来、Jev 页先用;
第 2 步整理别的插件页时接着用,不再做第二遍。第 1 步已经合进主分支;它在 `PluginsDrawer.tsx` 里只挪过上传起名的小函数,Jev 那几处和 `JevSettings.tsx` 没动过。

## 四、带上一条回复

### 4.1 发给 Jev 的样子

和测试里的 B 组一样,state 里在「玩家上一句」前面多一栏:

```
说明:            ……(原来那句)「上一条回复的最后几句」是这条回复之前、剧情接着往下的那一段,只用来了解前情,不用判。
上一条回复的最后几句: [{类型: 旁白, 内容: …}, {类型: 引号里的话, 内容: …}, …]
玩家上一句:       ……
本条回复:         [{句: 1, 类型, 内容}, …]
```

### 4.2 取哪几句

- 这条回复前面那条 AI 回复(它当前显示的那个分支),用视觉小说同一套切句;日中对照时只取中文那行(和本条回复一样);标签摘掉
- 取最后 N 句;不够 N 句有几句给几句,不再往更早的回复找
- 卡的开场白也算一条 AI 回复,所以第一轮回复也有前文
- 重新生成、插话:前文还是这条之前的那条 AI 回复
- 试判也带
- 背景、音乐、CG 的题也看得到前文(所有题共用同一份 state);测试只量了「谁说的」和表情,这几路没量过

### 4.3 设置

| 设置 | 存在哪 | 默认 | 范围 |
|---|---|---|---|
| 带上一条回复 | `plugin.jev` 的 `beforeLines` | 24 | 0–24(超过 24 没测过) |
| 「上一条回复」那句说明 | `plugin.jev.prompts.before`(问法框,高级里) | 后端默认 | 和别的问法一样 |

测试数据(同样的 1988 句,「谁说的」判对):不带 59.6%,带 8 句 64.9%,带 24 句 68.8%。

### 4.4 慢不慢、用多少

- 测试里 Jev 一次的中位数 0.112 秒 → 0.114 秒,感觉不出来
- 每次判断多约 700 token(带 24 句),也就是多约 39%;带 8 句多约 13%

## 五、技术细节

**连接(地址、模型名)**
- 后端 `app/annotate/client.py`:地址和模型名从设置里读(`app_settings` 的 `jev.endpoint`:`{url, model}`,不是秘密,通用设置接口能读写);
  没设就用官方的 `https://api.typesafe.ai/v1/systemone` 和 `jev-latest`。环境变量 `JEV_BASE_URL` / `JEV_MODEL` 优先(和 `JEV_API_KEY` 一样)
- 预热(`warmup`)连的是这个地址的主机。请求格式不变:中转要原样转发 TypeSafe 的 `systemone` 格式
- `/api/annotate/status` 多回地址、模型名、来源(这里设的 / 环境变量 / 官方默认);`/api/annotate/test` 用当前地址测

**用量**
- 新表 `jev_usage(day, requests, input_tokens)`,一天一行;每次问 Jev 回来以后 `UPSERT` 加上(并行的请求也不会互相盖掉)。迁移放 `app/migrations/core`
- 1 秒没回重发的那份:两份都发出去了,按两次记(第二份的 token 数按同一个请求算)
- `GET /api/annotate/usage` 回今天、近 7 天、本月、全部
- 前端原来的 `usd()`、视觉小说控制台的「约 $」改成 token 数

**带上一条回复**
- 后端 `app/annotate/judge.py`:`AnnotateInput` 加 `before: list[Line]`;`build_request` 在 `说明` 后面加那句说明、插入「上一条回复的最后几句」
  (`before` 为空时请求和今天逐字一样);`DEFAULT_PROMPTS` 加 `before`
- 后端 `app/api/annotate.py`:请求体加 `before`(最多 24 句,每句和本条回复的句子一样截 2000 字)
- 前端 `plugins/jev.ts`:`JevPluginConfig` 加 `beforeLines`(默认 24);`plugins/jevRun.ts`:`JevRunOptions` / `AnnotateRequest` 加 `before`
- 前端 `DebugApp.tsx` 的 `makeJevRun`:从 `before` 条目里找最后一条 AI 回复,按现在的标签设置合并 Jev 标注、切句、取最后 N 句

**页面**
- `SettingRow`(2.9 的画法):名字 · 控件 · 范围小标签 · 恢复默认 · 说明
- 新 `JevPage`(插件抽屉左栏一项);`JevSettings.tsx` 里的 `JevCommon` 拆进去,5 个插件页拿掉它、加指路行;`ModeBar` 没 key 时的提示改成链接
- 「哪几路交给 Jev」直接用各插件的配置(和插件页同一份状态),「详情 →」= 切到那个插件页
- API 抽屉底部加 Jev 状态行

**测试**
- `before` 为空时 `build_request` 输出和今天逐字一样(拿现在的写法当对照);带 `before` 时 state 的顺序和内容
- 前端取句:开场白、日中对照、不够 N 句、重新生成
- 地址:没设用官方;设了用设的;环境变量优先;`warmup` 连对的主机
- 用量:并行加不丢;重发按两次记;按天、周、月加对
- 两处切模式同步
