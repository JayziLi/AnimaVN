# 世界书：照酒馆的规则跑

日期：2026-09-29
状态：第一期已实现（2026-09-29）。实际做法和下面不一致的地方见文末「实现记录」

## 目标

酒馆用户把卡直接导进来就能玩，世界书的表现和在酒馆里一致。

用户原话：「主要是我需要酒馆的用户来玩，酒馆的生态太强了，我需要他们直接把卡导入进来」。

判断标准：同一张卡、同一段聊天记录，我们算出来的「本轮触发了哪些条目、各放在哪」和酒馆一致（带随机的功能除外）。

对照的酒馆版本：1.18.0（本机 `Desktop\SillyTavern`，提交 `8172dcd`）。规则都出自 `public/scripts/world-info.js` 的 `checkWorldInfo`。

## 现状

- 世界书是角色卡上的 `character_book` 字段，后端按自由 JSON 存
- 读卡时只留 5 个字段：`keys`、`content`、`enabled`、`insertion_order`、`comment`（`cardParser.ts` 和 `cardStore.ts` 各有一份 `normalizeBook`）
- 组装器把所有开着的条目整本拼进提示词，不看关键词（`assembler.ts` 的 `renderWorldInfo`）
- 「世界书(前)」「世界书(后)」两个块各输出一遍整本。库里 16 套预设有 14 套两个块都开着，世界书发了两遍
- 界面只读

### 会丢数据

导入酒馆卡后，5 个字段以外的内容在内存里就没了。之后改卡触发自动保存，`cardToStored` 把删减过的世界书写回数据库，原始字段永久丢失，导出的卡也不完整。

## 酒馆的规则

### 条目字段

卡里的写法（V2 规格）和酒馆内部名字的对应，照 `convertCharacterBook`：

| 卡里 | 含义 | 没写时 |
|---|---|---|
| `keys` | 主关键词 | |
| `secondary_keys` | 次要关键词 | 空 |
| `content` | 正文 | |
| `enabled` | 开关 | |
| `insertion_order` | 顺序号 | |
| `constant` | 常驻 | 否 |
| `selective` | 启用次要关键词 | 否 |
| `position` | `before_char` / `after_char` | **后** |
| `extensions.position` | 0–7，优先于上一行 | |
| `extensions.selectiveLogic` | 次要关键词逻辑 0–3 | 0 |
| `extensions.probability` / `useProbability` | 触发概率 | 100 / 开 |
| `extensions.depth` / `role` | 指定深度位置用 | 4 / system |

| `extensions.case_sensitive` / `match_whole_words` | 匹配方式 | 跟全局 |
| `extensions.exclude_recursion` / `prevent_recursion` / `delay_until_recursion` | 递归开关 | 否 |
| `extensions.group` / `group_override` / `group_weight` | 互斥分组 | 无 / 否 / 100 |

### 流程

1. 条目按顺序号从大到小排
2. 扫描文本：最近 N 条消息，每条写成「名字: 内容」，新的在前。条目可以再加上角色描述、人设、情景等
3. 逐条判断，先到先得：
   1. 关闭 → 跳过
   2. 延迟中 → 跳过；冷却中且不在粘性期 → 跳过
   3. 递归相关的开关
   4. 正文开头的 `@@activate` / `@@dont_activate`
   5. 常驻 → 触发
   6. 粘性期内 → 触发
   7. 没有关键词 → 跳过
   8. 主关键词任一命中才继续
   9. 没有次要关键词 → 触发；有则按逻辑判断
4. 次要关键词逻辑：0 任一命中、1 不是全部命中、2 全都没命中、3 全部命中
5. 互斥分组：同组留一条。粘性的优先；其次标了优先的里顺序号最大的；否则按权重随机
6. 概率：逐条掷骰，没过的这一轮不再考虑
7. 预算：按排好的顺序累加，超了的不加入；标了不受预算限制的照加
8. 递归：本轮新触发条目的正文加进扫描文本，再扫一遍，直到没有新条目
9. 按位置分发，同一位置里顺序号小的在前

### 匹配

- `/表达式/标志` 形式的关键词按正则匹配，其他选项都不管
- 普通关键词：不区分大小写时两边转小写
- 全词匹配只对不含空格的关键词生效，边界是 `\W`。中文字符都算 `\W`，所以中文关键词等于子串匹配
- 关键词里的宏先展开再匹配

### 位置

| 值 | 位置 |
|---|---|
| 0 | 角色描述前 |
| 1 | 角色描述后 |
| 2 / 3 | 作者注释上 / 下 |
| 4 | 聊天记录里指定深度，带角色 |
| 5 / 6 | 示例对话前 / 后 |
| 7 | 自定义出口 |

前、后各自套一次 `wi_format`；内容为空就什么都不输出。

## 设计

### 数据

- 条目在内存里保留全部字段：认识的字段解析成带类型的属性，整个原始对象另存一份
- 保存和导出时从原始对象出发，只覆盖被编辑过的字段。不认识的字段原样带走
- 两份 `normalizeBook` 合成一份
- 世界书本身的字段（`name`、`scan_depth`、`token_budget`、`recursive_scanning`、`extensions`）同样保留

### 触发引擎

新文件 `frontend/src/debug/lib/worldInfo.ts`，一个不依赖界面的函数：

```
activateWorldInfo({ entries, history, names, scanData, settings, maxContext, random })
  → { before, after, examplesTop, examplesBottom, depth[], activated[], skipped[] }
```

- `activated` 每条带触发原因（常驻 / 命中了哪个关键词 / 第几轮递归）
- `skipped` 每条带原因（没命中、概率没过、超预算、分组落选）
- 随机数从外面传进来，检查器预览和实际发送用同一次结果

组装器里 `worldInfoBefore` 取 `before`，`worldInfoAfter` 取 `after`，重复发送的问题同时消失。

### 全局设置

放在设置抽屉里，默认值照酒馆。卡的世界书自带 `scan_depth`、`token_budget`、`recursive_scanning` 时，酒馆不读这几项，我们也不读。

### 界面

- 卡编辑抽屉：条目可增删改，字段分「常用」（关键词、正文、常驻、位置、顺序）和「高级」两层
- 提示词检查器：列出本轮触发和没触发的条目及原因
- 预算条：世界书那一项显示实际进了提示词的量

### 已有角色卡

星绘、香奈美、诺亚、林翩翩、DeepSeek娘的条目都没写 `constant`，按酒馆规则会变成关键词触发。迁移脚本把这些条目标成 `constant: true`，位置标成「前」，表现不变。之后逐张卡调整。

迁移前备份数据库。

## 分期

### 第一期

- 字段完整保留
- 常驻、主 / 次关键词、四种逻辑、正则、大小写、全词
- 扫描条数（全局 + 单条）、额外扫描角色描述等
- 位置：前、后、示例对话前 / 后
- 概率、预算、递归（含三个递归开关）
- `@@activate` / `@@dont_activate`
- 触发明细、编辑界面
- 已有卡迁移

### 第二期

- 粘性、冷却、延迟：聊天记录要加一列存状态
- 互斥分组
- 独立世界书文件导入（酒馆的 `worlds/*.json`），绑到卡上

### 不做

- 全局 / 聊天 / 人设世界书
- 向量化、自动化 ID、角色筛选、生成类型筛选
- 自定义出口（要配合 `{{outlet::名字}}` 宏）

## 待定

1. **指定深度位置（4）**：之前定过组装器不做绝对深度注入。酒馆社区的卡常把状态栏、格式要求放在这个位置，不支持的话这些条目放不到原来的地方。选项：
   - 做：组装器加深度注入，预设块的 `injection_depth` 顺带也能生效
   - 不做：这类条目当作「后」处理，检查器里标出来
2. **作者注释上 / 下（2、3）**：我们没有作者注释功能。打算当作「后」处理
3. **回归用的卡**：本机酒馆只有自带的 Seraphina，没有社区卡可以测。需要几张目标用户会导入的真实卡

## 实现记录（2026-09-29）

第一期做完，和上面设计不一样的地方：

- **指定深度做了**，只给世界书条目用；预设块的 `injection_depth` 没动
- **作者注释上 / 下**没有当作「后」，而是按酒馆作者注释的默认位置放：聊天记录倒数第 4 条，system

## 宏引擎（2026-09-30）

用户的要求：「酒馆多少个我们实现多少个，我们不用但不能没有」。

### 做了什么

- 新的宏引擎 `frontend/src/debug/lib/macroEngine.ts`（语法和求值）+ `macroDefs.ts`（宏的总表）。
  对齐酒馆 1.18 默认开启的新宏引擎：从左到右求值、参数里可以套宏、`::` 分隔参数、
  `{{if}}…{{else}}…{{/if}}` 这样的成对块、`{{.变量}}` / `{{$变量}}` 简写和它的 15 个运算符。
  代码是照着行为自己写的，没有搬酒馆的源码（它是 AGPL）
- 内置宏 89 个，酒馆登记过的一个不少（测试里有名单核对）。指令模板那一批我们用不上，登记在册、恒为空
- 修掉两个老问题：`{{roll:1d100}}` 以前永远掷出 1；`{{// 注释}}` 以前会原样发给模型
- 变量：局部变量跟对话存（`debug_chats.variables`，迁移脚本 `migrate_chat_variables_column.py`），
  全局变量存本机 localStorage；导出 / 导入酒馆聊天文件时对应 `chat_metadata.variables`；分支带着变量走
- 组装器里每段文字只求一次，先后照酒馆：聊天记录 → 卡的字段 → 世界书 → 预设块（按编排）。
  预览算出来的变量不保存，真的发请求时才写回对话
- 顺带做了世界书的「自定义出口」（`{{outlet::名字}}`）和 `{{original}}`
- 「设置 › 宏」重做：按类别分组、可搜索的宏表；「这条对话的变量」和「全局变量」两个列表，能看能改能删

- `macros.oracle.test.ts`：203 个样本预设的全部启用块 + 样本卡的文字，共 6279 段，两边逐字相同，
  每个预设跑完之后的变量也相同。样本文件夹不在就跳过
- `macroEngine.test.ts`：75 条手写的边界情况，期望值同样是酒馆跑出来的，存在仓库里的 `macros.fixture.json`

靠对答案才发现的几条行为（读源码看不出来）：

- 参数里出现 `|`，整个宏作废、原样留着，连 `{{// a | b}}` 这种注释也一样。
  酒馆把 `|` 留给了还没做完的「过滤器」语法，而且词法分析器会因此跳过一段字，宏在哪儿结束都跟着变
- `{{user.name}}`、`{{user's}}` 能解析成用户名（名字后面的怪字符被跳过）
- `{{if 1::内容}}` 这种单行写法其实不生效，要写成 `{{if::1::内容}}` 或成对块
- 未知的成对宏 `{{foo}}x{{/foo}}` 输出是 `{{foo}}x}}`
- `{{space::-1}}` 原样留着（处理函数抛错）

### 和酒馆不一样的地方

- 时间类的宏按中文写（`15:04`、`2026年9月30日`、`星期三`、`3 小时前`）。酒馆跟着界面语言走，中文界面下也是这样
- `{{bot}}` 留作 `{{char}}` 的别名（酒馆新引擎里没有）
- 玩家自定义的宏可以起中文名，值里还能再套宏
- 卡的字段（`{{description}}` 等）取出来时再求一遍值；酒馆是提前替换好的，结果相同
- 中文变量名可以用 `{{getvar::好感度}}`，但不能用简写 `{{.好感度}}` —— 酒馆也一样，简写只认英文名
- `{{exampleSeparator}}` / `{{chatStart}}` 返回 `***`（酒馆默认上下文模板的值）
- `{{pick}}` 的种子算法不同：同一处每次挑到同一个，但挑到的那个和酒馆不是同一个
- `{{firstDisplayedMessageId}}`、`{{input}}`、`{{idleDuration}}` 目前没接真实数据（分别为空、空、「刚刚」）

### 没做

- 「消息前加名字」（`names_behavior`）：用户说暂时不做
- 预设导入导出时保留未知字段：还没做，见上文「预设样本回归」
- 变量面板里显示「哪个块写的」
- 第三方扩展的宏（`get_message_variable`、`summary` 等）：不属于酒馆本体

## 2026-09-30 整条链路对答案:发给 AI 的东西和酒馆一样吗

做法:真的把酒馆 1.18 跑起来(独立数据目录),接一个假的 AI 接口记下它发的请求;同样的卡、预设、用户消息喂给我们的 `assemble`,逐条比 role / content / name。5 个预设 × 5 张卡 = 25 组,正则脚本不比。测试在 `frontend/src/debug/lib/tavern.e2e.test.ts`,样本和抓取脚本在 `桌面\角色素材\_酒馆卡样本\e2e\`(`tools\README.md` 写了怎么重抓)。

结果:第一次 0 / 25,改完 25 / 25。为此改掉的行为(都在 `assembler.ts`,除非另注):

- 卡的字段先去首尾空白、求宏、去掉 `\r`;预设块的内容**不**裁首尾空白,只有彻底为空才不发
- 聊天记录最前面有一条 `[Start a new Chat]`(预设的 `new_chat_prompt`)
- 示例对话:每段前一条 `[Example Chat]`,段里每句是 `role: system` + `name: example_user / example_assistant`。name 现在一路带到 OpenAI 兼容接口(后端 `ChatMessage.name`)
- 合并相邻 system 时,上面两种标记和带 name 的消息不参与
- 内置块以外、标了 `system_prompt: true` 又不是绝对深度的块,酒馆不发,我们也不发
- 同一深度的预设块原样用换行接起来再整体去空白(块自己首尾的空行会留在中间)
- 预算的先后:固定内容 → 聊天记录(连同插在里面的深度块,从新往旧) → 示例对话(整段整段地给)。每条消息 +4、带 name 再 +1、整体留 3;世界书预算每次数 +6。额度 = 上下文大小 − 回复长度
- `{{original}}` 只在卡顶替主提示词 / 历史后指令时有值,同一段里只有第一个有值;别处原样留着。卡的这两段字会被求两遍宏(酒馆如此)
- 补了酒馆自带扩展注册的 9 个宏:`summary`、`authorsNote`、`charAuthorsNote`、`defaultAuthorsNote`、`reasoningPrefix/Suffix/Separator`、`charPrefix`、`charNegativePrefix`
- 故意不一样的只有一处:预算连最新一条用户消息都放不下时,酒馆会把它也丢掉,我们强留

测试里两边一致、但应用里还不一致的(待定):

- 「行首 `//` 当注释」是我们自己的功能,应用里默认开着。203 个样本预设里 49 个有这样的行,会被吞掉。测试里是关掉比的(`lineComments: false`)
- 应用里数 token 用的是粗估,酒馆用真分词器。内容没到预算边上时结果一样,到了边上可能差一条世界书或一条历史
- 应用里的预算 2026-10-04 起记在预设的 `openai_max_context` 里(和酒馆一样,换预设跟着变;「不截断」另记 `anima_context_off`);`openai_max_tokens` 仍不扣
- 没比的:采样参数、Claude 原生格式(酒馆有自己的一套转换)、群聊、继续 / 重新生成 / 代写、作者注释本身、玩家人设(测试里是空的)
