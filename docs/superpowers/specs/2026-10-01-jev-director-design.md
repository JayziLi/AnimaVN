# Jev 标注:每个插件可选「AI 写标签」或「Jev 标」—— 设计

状态:**已实现**(第二版,2026-10-01,未提交)。用户确认设计后按本文改完,实施结果见第十二节。
第一版(一个总开关、全部交给 Jev)和本文的差别见第十节。
**存法改过一次**(第十三节):第二版把 Jev 的标签缝进正文;现在正文只存模型原文,Jev 的标注另外存、用的时候合并
日期:2026-10-01
前置:立绘插件 `2026-09-23-vn-screen-sprite-plugin-design.md`、表情匹配 `2026-09-25-sprite-emotion-matching-design.md`、场景 / BGM `2026-09-23-vn-scene-pack-bg-bgm-design.md`、外语 `2026-09-25-lang-plugin-bilingual-design.md`、玩家台词 `plugins/player.ts`

## 一、背景

- 立绘、背景、BGM、玩家台词现在全靠 LLM 按插件块写标签。换个不带插件块的预设就全没了;弱一点的模型标签写歪、漏写(语料里 316/1171 句台词 AI 没写立绘标签,按规则不算角色的台词,不念)
- Jev(TypeSafe 的判断模型)给一段文字和几道选择 / 是非题,直接回答案和每个选项的概率。实测每次 0.16 秒,每条回复约 0.001 美元(数据见第九节)
- 用户定的(2026-10-01):
  - 给玩家两个选项:原来的「AI 写标签」和「Jev 标」,**每个插件在标题上切换**,不同模式显示不同设置
  - 只在本地调试台做,公网试玩站先不做
  - Jev 的 key 在切到 Jev 以后的设置里填,能测试
  - 「立绘和文字同步」做,默认开
  - 场景 / 音乐的门槛默认 0.6,可调
  - Jev 的提示词(问它的题)可以改

## 二、哪些插件有切换

| 插件 | 切换 | 说明 |
|---|---|---|
| 立绘 | 有 | Jev 判每句台词「谁说的 + 什么表情」 |
| 背景 | 有 | Jev 判「场景换没换、换到哪」 |
| BGM | 有 | Jev 判「气氛变没变、换哪首」 |
| 玩家台词 | 有 | Jev 判「这句是不是玩家说的」,是就弹成选项 |
| 语音 | 没有 | 本来就不写标签,情绪跟着立绘的表情走 —— 立绘是哪种模式,语音就跟着哪种 |
| 外语 | 没有 | 管日中对照的写法,不是标签。它的提示词会自动跟着变(第五节) |

默认全是「AI 写标签」,也就是现在的样子:不去切的人什么都不变。

## 三、界面:插件页显示什么

调试台的插件抽屉和视觉小说菜单里的插件页是同一个组件,两边一样。

### 3.1 标题栏

```
立绘                                   [ AI 写标签 | Jev 标注 ]
LLM 只写正文,每句的表情由 Jev 判断后补上 · 上一条回复:判了 11 句,最慢 0.23 秒
```

- 右边是二选一的切换;下面一行小字说明当前模式在做什么
- Jev 模式下,小字后半段显示上一条回复的统计(判了几句、最慢多久、有没有判失败的)
- 切到 Jev 但后端没有 key 时,小字变成提醒:「还没设 Jev 的 key,现在照旧由 AI 写标签」,点一下展开下面的 key 设置。也就是**没 key 时实际按 AI 模式跑**,不会出现两边都不写标签

### 3.4 Jev 通用设置(几个插件共用)

哪个插件切到 Jev,哪个插件里就出现这一块;**内容是同一份**,在哪里改都一样,块标题写明「几个插件共用」。默认收起,只露第一行(key 状态);展开后:

| 项 | 说明 | 默认 |
|---|---|---|
| Jev 的 key | 状态:没设置 / 已设置(这里填的)/ 已设置(后端环境变量)。输入框 + 保存 + 删除。只能写、读不回来 | — |
| 测试 | 点了真的问 Jev 一道小题,显示「通了 · 0.18 秒」或者出错原因(key 不对、连不上、超时) | — |
| **立绘和文字同步** | 开:这句的立绘 / 背景判完了才开始出字,画面和文字同时变。代价是你追上生成进度的那句,出字晚约 0.7 秒(日中对照约 1.2 秒),最多等 2 秒,超时先出字。关:文字照常边写边出,立绘 / 背景晚一点换 | **开** |
| 说话人的门槛 | Jev 判「这句不是角色说的」要多大把握才信;不够就还算角色的。高 = 少判成别人(更不容易漏念角色台词),低 = 更敢判成别人 | 0.8 |
| 通用说明(提示词) | 每次都放在最前面告诉 Jev 这是什么、谁是主角谁是玩家,见 3.5 | 见下 |
| 说话人题(提示词) | 立绘和玩家台词共用,见 3.5 | 见下 |
| 上一条回复的明细 | 每句判成了什么、把握多少、花了多久;花了多少 token / 美元 | — |

### 3.5 Jev 的提示词(可改)

每道题一个文本框,旁边写这道题能用的占位符,带「恢复默认」。改了马上生效(下一句开始用)。
占位符:`{{char}}` 角色名、`{{user}}` 玩家名、`{{n}}` 第几句、`{{line}}` 这句的原文(太长截前 50 字)、`{{current}}` 现在的背景 / 曲子名、`{{current_desc}}` 它的说明。

选项本身不在这里改:表情的选项是立绘包里的立绘名和说明,场景的选项是背景名和说明,音乐的选项是曲名和说明,在各自的素材表里改。说话人题的四个选项的**说明**可以改(选项本身固定是:角色 / 玩家 / 别人 / 不是说话)。

默认内容(就是实测用的):

| 题 | 在哪个插件 | 默认 |
|---|---|---|
| 通用说明 | 通用 | 视觉小说里 AI 刚写的一条回复,已经切成一句一句。主角是「{{char}}」,玩家是「{{user}}」(旁白里的「你」指的也是玩家)。 |
| 说话人题 | 通用 | 第 {{n}} 句 {{line}} 是谁说的? |
| 　选项「角色」 | | {{char}}本人说出口的话 |
| 　选项「玩家」 | | 玩家「{{user}}」说的话(旁白里写「你说」「你对她说」的那句) |
| 　选项「别人」 | | {{char}}以外的其他角色说的话 |
| 　选项「不是说话」 | | 不是有人在说话:心里想的、转述或引用的话、写在东西上的字、强调某个词 |
| 表情题 | 立绘 | 第 {{n}} 句 {{line}} 说出口的这一刻,{{char}}脸上是什么表情?结合前后文里情绪的起伏来判断,不要只看这句的字面。 |
| 场景题 | 背景 | 写到第 {{n}} 句时,人物在哪个场景?地点和白天、夜晚都要对上。还在「{{current}}」就选「不换」;只是提到、回忆、打算去某个地方也选「不换」。 |
| 　选项「不换」 | | 还在「{{current}}」{{current_desc}}:没换地方,白天夜晚也没变 |
| 音乐题 | BGM | 第 {{n}} 句这一刻的气氛,最适合放哪首背景音乐?和现在这首「{{current}}」还搭就选「不换」;气氛只是稍有起伏也选「不换」,明显转变(比如闲聊转为紧张、热闹转为伤感)才换。 |
| 　选项「不换」 | | 现在这首「{{current}}」{{current_desc}}还合适 |

改的时候的保护:删掉了 `{{n}}` 会提示「Jev 不知道问的是哪一句」(只提示,不拦);每道题最长 500 字。

**建议加一个「试判」按钮**(在通用设置里):拿当前对话最新一条 AI 回复,用现在的设置和提示词整条判一遍,按句列出结果(谁说的、表情、场景、音乐、把握),不改存档。改提示词、调门槛时能马上看到效果。一次不到 0.001 美元。

| 每个插件的模式 | 各插件标题栏 | AI 写标签 | AI 写标签 / Jev 标注 |
| Jev 的 key | 通用设置 | — | — |
| 立绘和文字同步 | 通用设置 | 开 | 开 / 关 |
| 说话人门槛 | 通用设置 | 0.8 | 0.5–0.95 |
| 换场景门槛 | 背景(Jev 模式) | 0.6 | 0.3–0.95,滑条两头写「多换」「少换」 |
| 换音乐门槛 | BGM(Jev 模式) | 0.6 | 同上 |

固定、不给调的(调了意义不大或者容易调坏):一条回复场景 / 音乐各最多换一次;带前面最多 24 句上下文;1 秒没回重发一份;写完后最多等 Jev 4 秒。

门槛是什么:Jev 每次选完都给一个把握(0–1)。门槛就是「把握到多少才真的换」。实测(93 条回复):

| 门槛 | 背景换了几条 | 音乐换了几条 | 例子 |
|---|---|---|---|
| 0.5(多换) | 18 | 29 | 多出一些可有可无的音乐切换 |
| **0.6(默认)** | **16** | **20** | 「诺亚走进店里 → 咖啡厅」(0.61,对)换得上;「DeepSeek娘 → 深夜」(0.71,错)也会换 |
| 0.8(少换) | 12 | 11 | 错的那次不换了,但咖啡厅、「剧烈的震动 → 紧张」(0.74)也漏了 |

## 四、一句话从写出来到显示的流程

```
模型写正文(Jev 模式的那几类标签不让它写;AI 模式的照写)
   ▼
前端切句(和视觉小说同一套):引号里的是台词、默认算角色的;「名字:」开头的算那个人的;其余是旁白
   ▼
一句写完(下一句开始、看到这句结尾的换行,或者整条写完)
   ▼
交给后端问 Jev:这条回复前面的句子(最多 24 句)、玩家上一句、各插件的选项和说明、
现在的背景和音乐、各插件的门槛和提示词。只问 Jev 模式的那几类:
   · 台词:立绘或玩家台词是 Jev → 问「谁说的」;立绘是 Jev → 再问「什么表情」
   · 第一句和旁白:背景是 Jev 且这条回复还没换过 → 问「在哪个场景」(含「不换」)
                  BGM 是 Jev 且这条回复还没换过 → 问「放哪首」(含「不换」)
   ▼
按门槛定结果,记成这句的标注:这句前面加 <bg:…><bgm:…><sprite:…> 或 <我>
(双语时加在这一对的日语行前面)。正文不动,标注存在分支信息里(第十三节)
   ▼
视觉小说读「原文 + 标注」合并后的样子:换立绘、背景、音乐,按表情合成语音
「立绘和文字同步」开着时:这句判完才开始出字
```

判断规则:
- 说话人:判成「不是角色」且把握 ≥ 说话人门槛 → 玩家:插 `<我>`(玩家台词是 Jev 且开着弹选项)/ 别人:不插,这句不念、不换立绘;否则算角色的,插 `<sprite:表情>`
- 场景 / 音乐:选的不是「不换」、和现在的不一样、把握 ≥ 门槛 → 换;这条回复之后不再问
- 判失败、超时:照没标处理,角色的台词沿用上一句的表情

## 五、混着用(比如立绘 Jev、背景 AI)

| 环节 | 规则 |
|---|---|
| 提示词块 | 只有 Jev 模式那几个插件的块不发;AI 模式的照发 |
| 提示词里的标签 | 历史先合并上 Jev 以前标的,再只摘掉现在是 Jev 模式那几类(历史、对话示例、世界书里的都摘);AI 模式那几类留着,模型才会继续照着写 |
| 外语块 | 开着的标签插件**全是** Jev 模式时,换成不提标签的版本;还有 AI 模式的就用原版(原版里写了标签放哪) |
| 模型的输出 | 原样存;Jev 模式那几类标签模型自己写了,显示时以 Jev 的为准;AI 模式的原样用 |
| 说话人怎么认 | 立绘是 Jev 时:Jev 判过的台词没带立绘标签就不算角色的(Jev 判成别人的就是不带标签);Jev 没判过的句子(还在判、改过)和立绘是 AI 时照现在的规则 |
| 存下来的回复 | 正文是模型原文;分支信息里记「这条哪几类是 Jev 标的 + 统计 + 每句的标注」(第十三节) |

中途切模式:已经存下来的回复不动,发给模型时按现在的模式处理(切回 AI 写,Jev 以前标的当示例发;切到 Jev,模型以前写的摘掉);从下一条回复开始按新模式标。

## 六、「立绘和文字同步」怎么表现

- 只在「你追上了生成进度」时起作用:正在显示的这句还没判完,就先不出字,对话框里保持「生成中」的样子;判完立绘 / 背景先换,接着开始打字,语音随后
- 你没追上的时候(读得比写得慢,绝大多数句子)没有任何影响:翻到时早判完了
- 最多等 2 秒,Jev 还没回就先出字(立绘晚点换)
- 每条回复第一句的首字因此晚约 0.7 秒(日中对照约 1.2 秒);之后的句子不受影响

## 七、后端

- `/api/annotate/lines`:请求里加上「要问哪几类」「各门槛」「各道题的提示词(没改的不传,用默认)」。场景、音乐换成「一道选择题 + 不换」
- `/api/annotate/defaults`(新):返回各道题的默认提示词 —— 默认值只在后端存一份,前端显示和「恢复默认」都从这里拿
- `/api/annotate/test`(新):用当前 key 问一道小题,回耗时或出错原因
- `/api/annotate/key`、`/status`、`/warmup`:不变。key 先看环境变量 `JEV_API_KEY`,没有就用设置里填的(存 `app_settings` 的 `secret.jev_key`,通用设置接口读写不了 `secret.*`)
- 常驻连接、1 秒没回重发:不变

## 九、实测数据(2026-10-01)

准确度(93 条真实回复、2464 句,逐句只看到这句为止):

| 项 | 结果 |
|---|---|
| 说话人 | AI 标过立绘的 855 句台词:854 句判成角色;AI 漏标的 316 句:289 句角色、20 句玩家(列出来看都是 Lj 说的)、7 句别人 / 不是说话 |
| 表情 | 和 AI 自己标的第一名一致 40%,AI 的在 Jev 前三 71%;09-28 盲判 39 道分歧 Jev 胜 17、AI 胜 12、都行 10 |

| 音乐(一道题 + 不换,门槛 0.6) | 93 条里换了 20 条,多在真转折上(「剧烈的震动 → 紧张」「想起那晚她站在河边 → 回忆」);两道题的问法太保守,只换了 10 条,还判反过一次 |

| 项 | 结果 |
|---|---|
| Jev 每次调用 | 平均 0.19 秒(前端发出到拿到结果),后端到 Jev 0.16 秒;108 次没有超过 1 秒的。每次新建连接的话平均 0.73 秒、最慢 28 秒,所以要常驻连接 + 重发 |

## 十三、存法:原文 + Jev 标注分开存(2026-10-01)

用户提的问题:用过 Jev 的对话切回 AI 写以后,历史怎么保持一致;也看不出一条回复 Jev 到底加了什么、模型原文是什么。定下来的做法:正文只存模型写的原文,Jev 的标注另外存,用的时候合并。不考虑导入历史(导进来没标签的照现在的默认显示)。

### 13.1 存什么

| 存在哪 | 内容 |
|---|---|
| `swipes[i]` | 模型写的原样,一个字不改 |
| `swipe_info[i].jev` | 原来的统计(`kinds`、判了几句、请求数、token、最慢、失败)+ `notes`:每句一条 `{at, check, tags}` |

- `at`:标签插在第几个字前面。按「原文摘掉这个分支 Jev 那几类标签」算 —— 模型不听话自己写了的,以 Jev 的为准
- `check`:这句开头 8 个字,用来核对原文改没改
- `tags`:加的标签(按插件模板写好);判成不用加的句子也记一条,`tags` 是空串 —— 切句靠它知道这句 Jev 判过
- 后端不用改:`swipe_info` 原样存取

### 13.2 谁用合并后的、谁用原文

| 用合并后的(原文 + Jev 标注) | 用原文 |
|---|---|
| 视觉小说的立绘、背景、音乐、语音、说话人 | 聊天区的编辑框 |
| 存档页缩略图、`{{current_bg}}` 这些宏、回复开始时的表情 | 导出给酒馆(酒馆那边看到的是干净的原文,不受影响) |
| 发给模型的历史(再按现在的模式摘,见下) | 视觉小说「历史」页的「显示原文」 |
| 聊天区默认显示 | 聊天区点「看原文」 |

发给模型的历史:先合并,再把**现在**是 Jev 模式的那几类整个摘掉。所以:
- 切回 AI 写:以前 Jev 标的那几类照样当示例发,模型接着写
- 切到 Jev:模型以前写的那几类也不发
- 实测(数据库副本):立绘从 Jev 切回 AI,新回复存的原文里一个标签都没有,发出去的提示词里带着 Jev 标的 `<sprite:温柔>`;背景、音乐、`<我>` 还是 Jev,一个都没发

### 13.3 聊天区怎么显示

- Jev 标过的回复,名字后面多一颗按钮「Jev 标注 · 立绘、背景… · 看原文」,点了切成模型原文(按钮变成「原文 · 点回 Jev 标注」)
- 合并后的正文里,Jev 加的标签用细框框出来,模型自己写的不框 —— 一眼看出哪些是 Jev 加的
- 编辑框里是原文,下面提示「这里是模型原文,Jev 的标签另外存着;改过的句子对不上,它的标签就去掉」
- 视觉小说开发者页的 Jev 统计后面多一句「标签另存,模型原文在调试台聊天区点『看原文』」;有对不上的会写「原文改过,N 句的标注对不上已去掉」

### 13.4 原文改了怎么办

- 编辑:合并时每条标注先看 `at` 处是不是 `check` 开头;不是就在全文找最近的同样开头(前面的句子改了长度,后面的标注跟着挪);找不到就扔掉这一句的标注。按钮上显示「N 句改过」
- 扔掉标注的句子当 Jev 没判过:照默认规则认说话人(引号里的算角色的)。其它句子不受影响。实现:切句的严格规则从「整条回复」改成「按句」(`parseReply` 的 `pendingFrom` 换成 `loose` 集合,还在判的句子也走它)
- 插话截断:截下来的新分支只留截到的那几句的标注,最后一句核对的字只核对到截断处。实测:读到第 5 句插话,新分支 396 字、5 条标注全对得上,完整版 49 条留在原分支
