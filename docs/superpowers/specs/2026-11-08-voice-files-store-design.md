## 要解决的事

现在声音的路径是「语音机上的路径」。导进来的声音如果语音服务在另一台电脑，要手动下载 zip、解压、填目录才能念。官方 api_v2 没有上传口，玩家不该管这些。

## 定了的（用户 11-04 至 11-08）

1. 玩家只填接口地址。AnimaVN 不启动语音服务。
2. 声音文件存在 AnimaVN 这台电脑的文件仓库，按指纹存。
3. 语音服务在同一台电脑：直接给仓库里的路径。在另一台：直接让它念，它没有的文件按指纹送过去，存进它自己的缓存。
4. GSV 这边用小插件，不改 GSV 源码；收文件要配对码，只接受本机、局域网、Tailscale。
5. 单机玩家也用同一个插件；老手可以不装，直接填地址。
6. 配置脚本：把插件放进玩家解压好的 GSV、建桌面快捷方式、显示接口地址（两台电脑时加配对码）。不做自动下载。
7. 33 个老声音全搬进仓库（最多 12.8 GB）。
8. 导出面板打开时不拉声音，缺文件明说，不做后台任务。
9. 声音去重：模型和所有参考音频都一样就用已有那条，有不同才新建「X 2」。
10. 语音服务页照模型页，没有「当前启用」；一张卡一个音色（10-25/26 定的）；优先级 GSV → Fish → IndexTTS → 中转站。
11. GSV v5 和「只有参考音频的声音挂 GSV」先不做（11-08）。

## 判断是哪条路

| 路线 | 条件 | 文件怎么到语音机 |
|---|---|---|
| same（同一台） | 插件能读到 AnimaVN 刚写的探针文件；没插件时看地址是不是 127.0.0.1 / localhost | 不用送，给仓库路径 |
| plugin（另一台） | 有插件、读不到探针 | 问它有哪些，缺的上传 |
| none | 没插件、地址不是本机 | 送不了，走原来的「导出文件、手动放」 |

不靠地址判断同机，因为 SSH 隧道的 127.0.0.1 其实在别的机器上。

## 老声音不用重新上传

老声音的路径（`D:/AnimaVoice/...`）留着，继续用。「搬进仓库」只是把文件拉回来记下指纹，这样能导出、能换电脑。规则按内容走：**路径非空就用路径；路径空、有指纹才走仓库**。所以缓存键、请求体都不变，已有的语音缓存继续有效，也不用「登记」步骤（比最初的设想简单）。

## 缓存键不依赖机器

路径空的声音，合成配置里写 `blob:<指纹>`，缓存键就按它算。真正发给语音服务前才换成实际路径，所以命中缓存时不碰网络，语音机关着也能放已缓存的句子。

## 插件接口（都在 `/anima/` 下）

| 接口 | 配对码 | 用途 |
|---|---|---|
| `GET /anima/info` | 不要 | `{plugin: 1, pair_ok}`，确认装了插件、配对码对不对 |
| `POST /anima/same-machine` | 不要 | `{path, sha256}` → `{same}`，同机探测；只读 64 KB 以内的小文件 |
| `POST /anima/have` | 要 | `{shas}` → `{have: {指纹: 路径}}` |
| `PUT /anima/blob/{sha}?ext=wav` | 要 | 上传，核对指纹后进缓存，返回路径 |
| `GET /anima/ref?path=` | 不要 | 原有的只读口，允许目录加上缓存目录 |

都只接受本机、私有网段、100.64.0.0/10。缓存在 GSV 目录的 `anima_cache/<前两位>/<指纹>.<扩展名>`。配对码存 `anima_pair.txt`，8 位，第一次启动时生成。整合包是 Python 3.9，插件不能用 3.10 语法。
