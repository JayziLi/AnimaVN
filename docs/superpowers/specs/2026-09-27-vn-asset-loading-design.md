# 视觉小说的素材等待页

状态：已实现（2026-09-27）

## 目标

用户原话：「现在的手机端每次使用，比如我换立绘、进游戏，都会看到立绘加载、素材加载，就只加载一半，就很奇怪。可不可以写个等待页，让玩家等待素材加载到手机/电脑上，素材齐全了再进入游戏。」

要求（用户定的）：「我预期 1–4 秒是可以的。如果超过 4 秒可以进去再加载，但是进游戏前，封面和前几个对话的素材要准备好，不然进去就是很奇怪的页面。」

## 已定的决定

| 项 | 决定 |
|---|---|
| 什么时候等 | 打开视觉小说、换角色（包括封面上点头像）、游戏里换立绘包 |
| 必须等（must） | 封面左边的头像圈；眼下这一句的背景和表情；往后 4 句（`AHEAD_LINES`）点到的表情和背景，这条回复不够 4 句就接着算下一条的开头；封面一露出来就看得到的表情（待机、纸上那张脸）。必须到齐才进，没有时间上限 |
| 尽量等（nice） | 封面悬停菜单、点一下才换的表情（排最前）；这个立绘包的全部表情；场景包的全部背景。从这一组开始算最多等 4 秒（`NICE_WAIT_MS`），到了就进，剩下的后台接着下 |
| 音乐 | 不等。刚打开、刚换角色时等待页撤下之前先不放音乐，带宽留给图 |
| 下载顺序 | must 全部下完才开始下 nice；清单变了（对话读完、表情模型认出来了）上一轮作废，作废的那轮不再去下 nice（否则会和新一轮的 must 抢带宽）。must 里头像（几 KB）排最前 |
| 「到齐」的标准 | 整张图下载完（`onload` / `onerror`），不提前 `decode()`：一口气解码三十来张大图又吃 CPU 又吃内存，手机上可能把页面挤崩；「只画一半」是边下边画造成的，下完再显示就不会 |
| 什么时候露等待页 | 没到齐 180ms 以后才露（有缓存时不闪）；露了至少停 0.7 秒（一闪而过像出错）。复用 VNScreen 原有的 `useLoadingVeil` |
| 刚打开 / 刚换角色 | 等待页撤下之前先黑着，封面也先不挂 —— 封面有一整套入场动画（划开、升起、淡入），不能在等待页底下偷偷播完 |
| 同一个角色换立绘包 | 不黑：旧立绘留在画面上，新的下完了淡入换上；慢了（180ms 以上）才盖等待页 |
| 游戏里换表情、换背景 | 立绘层、背景层、封面的立绘层都改成「新图整张下完才换上，没好先留着旧的」（`useSettledView`）。等待页之外没预载到的图也不会画一半 |
| 网很慢 | must 等了 12 秒（`SLOW_MS`）还没齐，等待页上出「网络有点慢 · 先进去」 |
| 等待页的样子 | 装饰靠角色素材（用户的审美偏好）：中间是这张卡按脸裁的头像，外面一圈进度（主题色）；上次停下的背景已经在缓存里的话虚化了垫底；下面一行小字「正在准备 · 头像 14/14 · 背景 3/17 · 立绘 9/15」；右下角沿用羽毛 + NOW LOADING。进度环 85% 按 must 走，剩下 15% 按 nice 的进度或 4 秒的时间走，进去时正好走满 |

## 代码

- `frontend/src/debug/vn/assetGate.ts`：`loadImage`（同一个地址一次打开里只下一次）、`useAssetGate`（闸门：按 key = 卡 + 立绘包重新等，同一个 key 放行后不再拦）、`useSettledView`（新图下完才换上）
- `frontend/src/debug/vn/VNLoading.tsx`：等待页；样式在 `vn.css` 的 `.vn-gate*`
- `frontend/src/debug/vn/VNScreen.tsx`：算 must / nice 清单、挂闸门、刚打开时不挂封面、不放音乐；原来「一口气同时下载全部立绘」的预加载去掉了
- `useSpritePacks.ts`、`useScenePlugin.ts` 各加一个 `ready`：这张卡的列表拿到了（切卡后要等一两次网络往返），`DebugApp` 合起来作为 `assetsReady` 传给 VNScreen

## 实测（2026-09-27，无头 Chrome，CDP 限速）

| 场景 | 结果 |
|---|---|
| 本机不限速，第一次 / 有缓存 | 1.4 秒 / 1.3–1.5 秒（有缓存时主要是打开视觉小说本身和头像圈的 304 往返） |
| 2 MB/s + 120ms 延迟，手机竖屏，诺亚第一次 | 约 5.8 秒（其中约 1.6 秒是开发服务器按需加载模块，打包后没有） |
| 同上，封面上换成芳乃（没下过） | 约 5.7 秒；芳乃一张立绘 PNG 近 1 MB，must 约 3.2 MB |
| 300 KB/s | must 没齐之前不进，齐了就进，没有死等 nice |
| 游戏里换立绘包（香奈美 私服 → 夜莺），2 MB/s | 0.8 秒露等待页，旧立绘一直完整地留着，2.1 秒新立绘完整淡入，4.6 秒进回游戏 |

## 手机上的立绘用 WebP（用户同意，2026-09-27）

- 触屏设备（`pointer: coarse`：手机、平板）上 `spriteImageUrl` 带 `&w=1024`，后端转成 WebP（质量 85）。电脑照旧用原图 PNG
- 后端 `app/images.py` 的 `shrink_image` 改了规则：比要求的宽就等比缩小，**窄的保持原尺寸只换格式**（原来窄的直接发原图）；转出来不比原图小就还是发原图。结果按「原图内容哈希 + 宽度」缓存在内存里（最多 64 MB），同一张图只转一次
- 只动立绘：背景本来就是 JPG，手机竖屏时背景被放大裁切，缩了会糊
- 封面取色用的 `shrunk()`（`titleArt.ts`）改成替换地址里已有的 `w`，不再追加出两个 `w`
- 实测：芳乃 934 KB → 146 KB、香奈美 1094 KB → 138 KB、诺亚 596 KB → 122 KB；芳乃一整包 15 张 13.7 MB → 2.2 MB。脸部放大 2 倍并排看不出区别
- 手机 2 MB/s 第一次进芳乃：必须等的 1.7 秒左右就齐，立绘全部下完 5–6.6 秒（原来光立绘就要 7 秒以上）；「进入」仍按规则最多等 4 秒的 nice，现在 nice 里占大头的是背景（芳乃 17 张共 4.3 MB）

## 没做的

- 封面头像圈（`/sprites/face`）是 `no-cache` + ETag，每次打开都要问一遍后端（304），头像圈是立绘包那边的设计，没动
